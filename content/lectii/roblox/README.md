# Roblox Studio — Curriculum Code Kids Play

**Curs:** Roblox Studio (`c12`)  
**Public:** **12+ ani** (bandă site: Micii Programatori)  
**Formă:** **4 module × 10 lecții** · badge la finalul fiecărui modul  
**Limbaj scripting:** Luau (Roblox)  
**Proiect pe verticală (intenționat):** **un singur Obby** care crește M1→M4 — nu 4 jocuri noi de la zero

*Premisă 12+:* ritm și vocabular ca la C++/Unity pe landing; M1 rămâne fără cod ca să nu amestecăm Studio + sintaxă în aceeași oră, dar din M2 putem cere Minim mai ferm (erori citite din Output, prefix `Srv_`/`Cli_`).

---

## Ideea de bază

| Modul | Badge | Ce înveți | Ce termini (capstone) |
|-------|--------|-----------|------------------------|
| **M1** | **Place Builder** | Studio + construcție (fără / cu cod minim) | **Lumea Obby** (start → finish, checkpoint vizual) |
| **M2** | **Script Starter** | Luau + client/server + **funcții înainte de evenimente** | **Mecanisme pe același Obby** (ușă / monedă) |
| **M3** | **Game Logic** | leaderstats, GUI, RemoteEvent, securitate Minim | **Același Obby** + scor / checkpoint-uri |
| **M4** | **Roblox Creator** | ModuleScript → DataStore Minim → NPC/shop + publish | **Același Obby**, versiune publicată |

**De ce un Obby, nu 4 proiecte separate:** portofoliu clar („uite cât a crescut jocul meu”) + reutilizare de skill-uri (ca Scratch L9→L10 pe același proiect).  
**Risc:** Place pierdut / stricat. **Plasă:** la începutul **M3** și **M4**, copilul poate porni de la un **Place de bază al profesorului** dacă Obby-ul propriu nu mai e jucabil.

**Convenții CKP (ca Scratch):** Minim vs Complet · checkpoint-uri dese · L9 mini-proiect · L10 completare + prezentare + insignă  
**Nume Place:** `Prenume_Nume_M1` … (copii M2/M3/M4 pe măsură ce avansezi)  
**Scripturi:** prefix **`Srv_`** / **`Cli_`** — din M2
